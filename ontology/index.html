An ontology is a shared model of what exists in a domain, written so machines can reason with it.

It names the kinds of things, the things themselves, how they relate, and the rules that hold. From those rules a reasoner can work out facts nobody typed in.

Class

Kinds of things

Categories like Dog, Service, or Customer.

≈ a table, a type, or an interface

Individual

Actual things

Specific members like Rex or Checkout.

≈ a row, or an object instance

Property

Relationships

Links like owns or dependsOn, with rules about what they connect.

≈ a foreign key, but with meaning

Inference

Rules → new facts

"Every Dog is an Animal" + "Rex is a Dog" ⇒ "Rex is an Animal".

This is what a schema alone can't do

Where you'll meet ontologies: Schema.org markup on web pages, Wikidata, FHIR and SNOMED in healthcare, enterprise knowledge graphs, and the data feeding search and LLM retrieval. The "Behind the scenes" tab in the sandbox shows the real standard format (OWL in Turtle syntax).
